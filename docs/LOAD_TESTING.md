# Нагрузочное тестирование HTTP API

## Назначение

Проверить доступность, параллельную обработку HTTP-запросов и совместимость JSON-ответа с ESP32 при 10, 50 и 100 клиентах. Скрипт измеряет latency p50/p95/p99, throughput и ошибки.

## Запуск

На машине, где доступен API:

```powershell
python tools/load_test_api.py --url http://127.0.0.1:8765 --clients 10 50 100 --requests-per-client 3
```

Для отдельного этапа:

```powershell
python tools/load_test_api.py --url http://127.0.0.1:8765 --clients 50 --requests-per-client 10
```

## Важное предупреждение

Скрипт не читает и не передаёт HAR, cookies, токены или данные сессии. Он отправляет только обычные GET-запросы к указанному API.

Однако каждый GET регистрирует географическую зону. Если тестировать работающий полный коллектор, эти зоны могут попасть в AreaRegistry и вызвать реальные upstream-запросы FR24. Поэтому:

- сначала запускайте тест на стенде без активного FR24-коллектора;
- либо проводите его в согласованное окно на тестовом экземпляре;
- не запускайте нагрузочный тест на рабочем сервере без оценки количества новых областей и upstream-лимитов.

## Сценарий и ограничения

- Каждый виртуальный клиент использует отдельные координаты.
- Все запросы выполняются конкурентно; повторные запросы одного клиента используют ту же зону.
- Проверяются HTTP 200, JSON, обязательные поля ответа и согласованность total с длиной ac.
- Скрипт не эмулирует Wi-Fi, задержки ESP32, расписание опроса ровно 10 секунд или ответы FR24.
- Это тест HTTP/API, а не доказательство производительности upstream-источника или гарантии свежести данных для 100 удалённых зон.

## Критерии приёмки

Для каждого размера нагрузки:
- errors = 0;
- все ответы содержат обязательный JSON-контракт;
- total равен количеству элементов в ac;
- сохранить p50/p95/p99 и throughput для сравнения последующих версий.

Результаты теста следует прикладывать к отчёту о тестировании, не публикуя сетевые секреты и HAR.
