# FR24 Standard API — альтернативный источник FlightRadarAPI

## 1. Назначение и статус

Документ описывает ветку `feature/flightradarapi-all-fields` репозитория [FR24_Standard_API](https://github.com/alisatsyplyarova-art/FR24_Standard_API).

В этой ветке источник данных — сторонняя Python-библиотека **FlightRadarAPI 1.7.1**. Сборщик не отправляет собственные gRPC-Web/protobuf-запросы FR24 и не использует HAR-файл. Это отдельная реализация источника, сохранённая в отдельной ветке; действующая ветка `main` не заменяется.

FlightRadarAPI — неофициальный SDK, читающий публичную live-ленту сайта Flightradar24. Это не официальный коммерческий API и не ADS-B-приёмник.

## 2. Поток данных

```text
FR24 public live feed
        |
        v
FlightRadarAPI 1.7.1
        |
        | Flight objects
        v
main.py
  - проверка координат и времени
  - нормализованные поля Standard API
  - полный набор публичных атрибутов -> source_fields
        |
        v
AircraftCache
  - актуальные атрибуты
  - история до 120 точек
  - хранение до 30 минут
  - stale после 120 секунд
        |
        +--> GET /health
        +--> GET /aircraft
        +--> GET /api/radar
        +--> GET /v2/lat/{lat}/lon/{lon}/dist/{nm}
```

Сборщик опрашивает библиотеку примерно каждые 10 секунд. Центр и радиус берутся из `radar_config.json` до первого запроса ESP32, затем используются параметры последней области, переданной через совместимый маршрут `/v2/...`.

## 3. Установка и запуск

Требования:
- Windows 10 / Windows Server 2019 или новее;
- Python 3.11+;
- `FlightRadarAPI==1.7.1`.

Установка в отдельном виртуальном окружении:

```powershell
py -3.14 -m venv venv
.\\venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Создайте `radar_config.json` по образцу `radar_config.example.json`, указав `latitude`, `longitude` и `radius_km`. Необязательный параметр `fetch_details` включает подробные запросы по каждому самолёту; по умолчанию `false`.

Запуск:

```powershell
python main.py
```

Локальный HTTP API слушает `0.0.0.0:8765`.

HAR-файл, cookies и учётные данные FR24 этой ветке не требуются.

## 4. Поля от FlightRadarAPI

Базовый вызов:

```python
flights = fr_api.get_flights(bounds=bounds)
```

Каждый элемент — объект `Flight`. В текущей версии SDK в нём предусмотрены следующие публичные атрибуты:

| Атрибут SDK | Значение |
|---|---|
| `id` | внутренний идентификатор FR24 |
| `icao_24bit` | ICAO 24-bit |
| `latitude`, `longitude` | координаты |
| `heading` | курс, градусы |
| `altitude` | высота, футы |
| `ground_speed` | путевая скорость, узлы |
| `squawk` | код ответчика |
| `aircraft_code` | тип/код воздушного судна |
| `registration` | регистрация |
| `time` | время позиции, Unix seconds |
| `origin_airport_iata` | IATA вылета |
| `destination_airport_iata` | IATA назначения |
| `number` | номер рейса |
| `airline_iata` | IATA авиакомпании |
| `on_ground` | признак нахождения на земле |
| `vertical_speed` | вертикальная скорость, ft/min |
| `callsign` | позывной |
| `airline_icao` | ICAO авиакомпании |

### Полное сохранение полей

Сборщик не ограничивается жёстким списком полей модели. Функция `_public_flight_fields()` перебирает публичные атрибуты экземпляра SDK через `vars(flight)` и преобразует значения в JSON-совместимый формат.

Полный набор исходных атрибутов каждого борта хранится в:

```json
{
  "source_fields": {
    "id": "…",
    "icao_24bit": "…",
    "latitude": 0.0,
    "longitude": 0.0
  }
}
```

Пример сокращённый. Фактический объект содержит все публичные атрибуты, присутствующие у данного экземпляра Flight. Если новая версия SDK добавит публичные поля, они будут автоматически сохранены без изменения модели и кэша.

Нормализованные поля Standard API остаются отдельно: `callsign`, `flight_number`, `registration`, `origin`, `destination`, `aircraft_type`, `squawk`, `vertical_speed_fpm`, `icao_hex`, `altitude_ft`, `speed_kt`, `track`, `on_ground` и другие доступные поля. Это сохраняет совместимость существующих клиентов.

### Детальные сведения

У FlightRadarAPI есть режим `get_flights(details=True)`. Он делает отдельные запросы за подробностями каждого рейса и добавляет к объектам сведения о самолёте, авиакомпании, аэропортах, статусе, времени и trail.

Этот режим управляется параметром `fetch_details` в `radar_config.json` и намеренно выключен по умолчанию: число дополнительных запросов зависит от количества самолётов и может заметно увеличить нагрузку и риск ограничений со стороны FR24. Если указать `"fetch_details": true`, все новые публичные атрибуты также автоматически попадут в `source_fields`.

## 5. Кэш и возраст данных

- До 120 точек истории на один борт.
- Самолёт хранится в кэше до 1800 секунд после последнего обнаружения.
- После 120 секунд без обновления запись считается устаревшей (`is_stale=true`).
- `/aircraft` возвращает активные и сохранённые устаревшие записи.
- `/api/radar` и `/v2/...` используют только активные записи.

Время SDK `Flight.time` нормализуется для расчёта возраста позиции. В JSON сохраняются исходные атрибуты SDK в `source_fields` и отдельные нормализованные поля Standard API.

## 6. HTTP API

### `GET /health`

Состояние сервера, количество активных самолётов, активная область и имя источника данных.

### `GET /aircraft`

Полный снимок кэша: все сохранённые поля, `source_fields`, история координат, текущая позиция, вычисленный курс, возраст записи и признаки stale.

### `GET /api/radar`

Плоский список активных самолётов. Помимо совместимых полей, содержит доступные поля кэша и вложенный объект `source_fields`.

### `GET /v2/lat/{latitude}/lon/{longitude}/dist/{distance}`

Совместимый маршрут для прошивки ESP32. `distance` задаётся в морских милях (NM), допустимый диапазон — до 500 NM. Ответ сохраняет корневые поля `ac`, `msg`, `now`, `total`, `ctime`, `ptime`; каждая запись содержит привычные поля `fr24_id`, `lat`, `lon`, `seen`, `seen_pos`, `flight`, `track` и дополнительные поля кэша, включая `source_fields`.

### `GET /protobuf/latest`

Диагностический маршрут совместимости. FlightRadarAPI не предоставляет исходные protobuf-кадры, поэтому в этой ветке кадры не создаются и список остаётся пустым. Для просмотра полей используйте `source_fields`.

## 7. Ограничения и безопасность

- FlightRadarAPI — сторонняя неофициальная библиотека. Работа зависит от доступности сайта FR24, его антибот-защиты и изменений веб-лент.
- Нельзя считать, что каждый атрибут заполнен у каждого самолёта: пустые/неизвестные значения зависят от исходной записи FR24.
- `source_fields` сохраняет все публичные атрибуты, которые SDK фактически передал. Он не может вернуть данные, которых нет в ответе FR24 или которые SDK не разобрал.
- Режим подробностей `details=True` требует дополнительных запросов на каждый борт.
- Соблюдайте условия использования Flightradar24; для коммерческого доступа используйте официальный API FR24.
- Не публикуйте локальную конфигурацию, логи, cookies, токены и виртуальное окружение.

## 8. Проверки этой доработки

Выполнена проверка вспомогательного преобразования полей: сохраняются строковые, числовые, логические, словарные и списочные значения; приватные атрибуты с подчёркиванием не экспортируются; нечисловые значения float (NaN/Infinity) заменяются на JSON-safe `null`.

Полный интеграционный тест с живой лентой FR24 и проверка совместимости на физической ESP32 в рамках этой доработки не выполнялись.
