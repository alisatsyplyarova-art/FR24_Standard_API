Локальный HTTP API-сервер, получающий текущие рейсы Flightradar24 через неофициальную Python-библиотеку FlightRadarAPI.

## Возможности

- Опрос данных сайта Flightradar24 через FlightRadarAPI каждые 10 секунд.
- Не требуются ключ API и учётные данные FR24.
- Кэширование координат, истории, курса, высоты и путевой скорости.
- Сохранение всех публичных атрибутов объектов FlightRadarAPI в поле `source_fields`, включая новые поля SDK без изменения модели.
- Хранение самолётов в кэше до 30 минут после последнего обнаружения.
- Пометка самолётов как устаревших через 2 минуты без обновления.
- Ограничение истории каждого самолёта 120 точками; устаревшие борта не выдаются в ESP32-совместимые радарные маршруты.
- HTTP API на порту 8765.
- Фильтрация по расстоянию в морских милях (NM).
- Сохранены прежние маршруты API и формат ответов для ESP32.

## Требования

- Windows 10 / Windows Server 2019 или новее.
- Python 3.11 или новее.
- FlightRadarAPI 1.7.1.
- requests 2.31.0 или новее (для совместимых вспомогательных модулей).

## Настройка

Создайте radar_config.json на основе radar_config.example.json. Укажите latitude, longitude и radius_km. Необязательный параметр `fetch_details` включает дополнительные запросы за подробностями каждого рейса; по умолчанию он равен `false`. HAR-файл и авторизация FR24 для этой версии не нужны.

    python main.py

## API

- GET /health — состояние сервера, число самолётов, активная область и используемый источник данных.
- GET /protobuf/latest — совместимый диагностический маршрут; FlightRadarAPI не предоставляет исходные protobuf-кадры, поэтому список кадров будет пустым.
- GET /aircraft — полный снимок кэша, включая историю координат и доступные атрибуты рейса; содержит `is_stale`, `seen_seconds`, `active_count` и `stale_count`. Самолёты хранятся 30 минут после последнего обнаружения, статус устаревшего присваивается через 2 минуты.
- GET /api/radar и GET /v2/... — только активные самолёты (обновлявшиеся в последние 2 минуты).
- GET /api/radar — плоский совместимый список бортов с доступными атрибутами рейса.
- GET /v2/lat/{latitude}/lon/{longitude}/dist/{distance} — запрос ESP32; расстояние передаётся в морских милях (NM).

### Источник и полнота данных

Сборщик использует неофициальную библиотеку FlightRadarAPI, которая получает общедоступные данные с сайта Flightradar24. Это не официальный API FR24 и не ADS-B-приёмник. Библиотека не требует ключа API или логина для текущего режима, но доступность зависит от сайта FR24, его антибот-защиты и изменений веб-интерфейса.

В этой ветке исходный protobuf/gRPC-Web поток не используется. Поэтому поля, которых FlightRadarAPI не возвращает, не могут быть восстановлены; protobuf-кадры не генерируются и не имитируются. Все публичные атрибуты объекта `Flight`, полученные от SDK, сохраняются без потери в `source_fields` каждого самолёта и возвращаются через `/aircraft`, `/api/radar` и `/v2/...`. Это включает исходные имена SDK: `id`, `icao_24bit`, `latitude`, `longitude`, `heading`, `altitude`, `ground_speed`, `squawk`, `aircraft_code`, `registration`, `time`, `origin_airport_iata`, `destination_airport_iata`, `number`, `airline_iata`, `on_ground`, `vertical_speed`, `callsign`, `airline_icao` — если они присутствуют в ответе FR24. Нормализованные поля Standard API остаются доступны отдельно для совместимости. Поля, добавленные будущими версиями SDK, также сохраняются автоматически.

Расширенная информация о рейсе (детальные сведения самолёта, авиакомпании, аэропортов и след) запрашивается библиотекой отдельно для каждого борта через `get_flights(details=True)`. Режим управляется параметром `fetch_details` в `radar_config.json` и по умолчанию выключен: он создаёт дополнительные запросы на каждый самолёт. Если включить его, новые публичные атрибуты также попадут в `source_fields`.

### Работа с Flight Radar-D & Clock 1.1.127

ESP32 передаёт серверу текущие координаты центра радара и выбранный радиус через
`/v2/lat/{latitude}/lon/{longitude}/dist/{distance}`. Сервер использует эти параметры
не только для фильтрации ответа, но и для формирования области следующего запроса
к ленте рейсов Flightradar24 через FlightRadarAPI. Поэтому данные больше не ограничены постоянной областью из
`radar_config.json`.

`radar_config.json` служит начальной областью сбора до первого запроса от ESP32.
После первого запроса активная область меняется вслед за центром и масштабом радара.
В журнале коллектора выводятся текущие координаты и радиус; `/health` показывает
активную область в поле `active_area`, а также источник данных в поле `source`.

Если к серверу подключено несколько радаров с разными координатами, используется
область последнего поступившего запроса (режим одного активного радара).

fr24_id — внутренний идентификатор FR24, не ICAO HEX.

## Ограничения и безопасность

FlightRadarAPI — неофициальный проект для образовательного/личного использования. Он может перестать работать при изменениях сайта или ограничениях доступа со стороны FR24. Бесплатность библиотеки не означает гарантированный SLA или разрешение на коммерческое использование: соблюдайте условия Flightradar24. Не публикуйте локальную конфигурацию, логи и виртуальное окружение.
