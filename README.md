# FR24 Standard API

Локальный сервер-посредник между Flightradar24 LiveFeed и несколькими радарами ESP32.

> **Текущий статус разработки:** ветка `feature/multi-area-cache-5s`. Это отдельная ветка разработки; перед эксплуатацией выполните тестирование на своём HAR и сети.

## Что делает сервер

1. Принимает запросы ESP32 по совместимому маршруту `/v2/lat/{lat}/lon/{lon}/dist/{radius_nm}`.
2. Собирает поступившие запросы в течение 5 секунд.
3. Объединяет пересекающиеся круговые области в одну охватывающую область.
4. Оставляет удалённые области отдельными.
5. Получает данные для каждой сформированной области через существующий FR24 LiveFeed gRPC-Web/HAR-механизм.
6. Обновляет общий кеш самолётов и выдаёт каждому ESP32 данные, отфильтрованные по его координатам и радиусу.
7. Кеширует одинаковый ответ API на 5 секунд, чтобы параллельные одинаковые запросы не повторяли фильтрацию.
8. Дополняет данные самолётов ICAO HEX через отдельный FR24 FlightDetails gRPC-Web запрос, если идентификатор доступен и ICAO ещё не получен. Обогащение выполняется отдельно от декодирования LiveFeed и использует интервалы повторных попыток для NOT_FOUND и прочих ошибок.

## ICAO

В API `/aircraft` доступны поля `icao_address` (числовое значение) и `icao_hex` (шестизначный HEX). Обычная запись LiveFeed не всегда содержит ICAO, поэтому сервер получает его отдельным запросом FlightDetails. Пока FlightDetails не вернул подтверждённое значение, поля могут оставаться `null`. Исторический контрольный пример и описание protobuf/gRPC-Web находятся в [исследовательском документе](docs/FR24_FLIGHTDETAILS_ICAO_RESEARCH.md). Документ фиксирует состояние исследования на 28.11.2026; разделы о невыполненной интеграции описывают состояние на тот момент, а не текущую версию кода.

## Важные интервалы

| Параметр | Значение |
|---|---:|
| Опрос одного ESP32 | не чаще 1 раза в 10 секунд (настройка прошивки) |
| Окно сбора запросов | 5 секунд |
| TTL ответа одинакового HTTP-запроса | 5 секунд |
| Срок активности зарегистрированной зоны | 35 секунд |
| Целевой интервал цикла коллектора | 10 секунд |

Окно сбора и TTL HTTP-ответа — разные механизмы. Число обращений к FR24 зависит от количества **непересекающихся** сформированных областей. Объединение зон уменьшает число запросов, но не гарантирует один запрос при географически удалённых радарах.

## Важно о FR24

Сервер использует текущий механизм проекта: FR24 LiveFeed, gRPC-Web, protobuf и локальный HAR-файл. FlightDetails также вызывается отдельным gRPC-Web запросом. Это не официальный REST API FR24 Standard subscription. HAR содержит данные сессии и не должен попадать в GitHub. Соблюдайте условия доступа и ограничения FR24.
