# FR24 Standard API

## Документация

Подробное описание архитектуры, protobuf-декодирования, HTTP API, установки, диагностики, ограничений и готовое техническое задание для Claude Code:

- [FR24 Standard API — техническое руководство и инструкция для разработчика](docs/FR24_STANDARD_API_TECHNICAL_GUIDE_RU.md)


Локальный сборщик данных Flightradar24 LiveFeed с HTTP API.

## Возможности

- Опрос FR24 каждые 10 секунд.
- Декодирование protobuf / gRPC-Web, включая обычные и выбранные рейсы.
- Извлечение статистики источников и флагов доступности EMS.
- Кэширование координат воздушных судов.
- Удаление устаревших позиций.
- HTTP API на порту 8765.
- Фильтрация по расстоянию в морских милях (NM).

## Требования

- Windows 10 / Windows Server 2019 или новее.
- Python 3.11 или новее.
- requests 2.31.0 или новее.
- Собственный HAR-файл FR24 LiveFeed.

## Установка

    git clone https://github.com/alisatsyplyarova-art/FR24_Standard_API.git
    cd FR24_Standard_API
    python -m venv venv
    .\venv\Scripts\Activate.ps1

## Настройка

Создайте radar_config.json на основе radar_config.example.json. Укажите latitude, longitude и radius_km. Подготовьте собственный www.flightradar24.com.har.

HAR-файл не публикуйте: он может содержать идентификаторы устройства и данные сессии.

## Запуск

    python main.py

## API

- GET /health — состояние сервера, число самолётов в кэше и активная область сбора.
- GET /aircraft — все воздушные суда в кэше.
- GET /v2/lat/{latitude}/lon/{longitude}/dist/{distance} — запрос ESP32; расстояние передаётся в морских милях (NM).

### Работа с Flight Radar-D & Clock 1.1.127

ESP32 передаёт серверу текущие координаты центра радара и выбранный радиус через
`/v2/lat/{latitude}/lon/{longitude}/dist/{distance}`. Сервер использует эти параметры
не только для фильтрации ответа, но и для формирования области следующего запроса
к FR24 LiveFeed. Поэтому данные больше не ограничены постоянной областью из
`radar_config.json`.

`radar_config.json` служит начальной областью сбора до первого запроса от ESP32.
После первого запроса активная область меняется вслед за центром и масштабом радара.
В журнале коллектора выводятся текущие координаты и радиус; `/health` показывает
активную область в поле `active_area`.

Если к серверу подключено несколько радаров с разными координатами, используется
область последнего поступившего запроса (режим одного активного радара).

fr24_id — внутренний идентификатор FR24, не ICAO HEX.
